# VigilAgent — Autonomous Visual Inspection Agent (OpenCV 5 + AWS)

VigilAgent inspects a photograph of a workstation or storage zone and
returns a verdict — **PASS**, **FAIL**, or **HUMAN_REVIEW** — with visual
evidence and a complete decision trace. It is an *agent*, not a fixed
pipeline: what it measures changes what it does next. A blurry photo is
corrected and re-measured; an unreadable lot label is retried after
rectification; every suspected defect must survive an independent zoomed
second look before it can fail a station; and anything the agent cannot
resolve is escalated to a human instead of being guessed.

Built for the **OpenCV AI Competition 2026, powered by AWS** — targeting
the Overall awards and the **Agentic Vision Award**.

## How it works

1. **Plan** — an ArUco marker identifies the zone; the zone's enrolled
   plan (slots, free areas, label area, expected lot string) selects the
   tools and thresholds.
2. **Quality gate** — OpenCV measures blur (Laplacian variance), contrast
   and exposure. On failure the agent applies the correction matching the
   measured issue (CLAHE, gamma, sharpening) and re-measures, up to 3
   rounds. Still unusable → HUMAN_REVIEW.
3. **Perceive** — QR lot-label decoding; ORB + homography alignment to
   the enrolled reference; reference difference; region classification
   (missing item, slot anomaly, stain, foreign object).
4. **Doubt → re-inspect** — a failed QR decode is retried on a rectified
   upscale; each candidate defect region is confirmed or dismissed by an
   enlarged-crop second detector.
5. **Decide & report** — verdict, findings with bounding boxes, an
   annotated image, and the full JSON trace of every tool call and
   decision. On AWS, reports and evidence persist to S3 with a DynamoDB
   index; locally they are returned in the HTTP response.

## Quick start (local)

```bash
python3 -m venv .venv
.venv/bin/pip install --upgrade pip   # a fresh venv's stock pip may fail to
                                      # resolve opencv-python-headless 5.x
.venv/bin/pip install -r requirements.txt
.venv/bin/python data/gen_scenes.py          # build the evaluation scenes
.venv/bin/python evaluation/run_eval.py      # 10-case end-to-end evaluation
.venv/bin/uvicorn app.main:app --port 8080   # demo at http://localhost:8080/
```

## Deploy on AWS

Prerequisites: an AWS account, AWS SAM CLI, Docker.

```bash
cd infra
sam build
sam deploy --guided        # creates: HttpApi, Lambda (arm64 container),
                           # S3 evidence bucket, DynamoDB index
```

The deploy outputs the working endpoint URL. The same container image
(`infra/Dockerfile`, FastAPI served through the AWS Lambda Web Adapter)
also runs stand-alone: `docker build -f infra/Dockerfile -t vigilagent .`

## Test

- `evaluation/run_eval.py` — end-to-end verdicts against ground truth on
  the generated set (clean, 4 defect families, 5 degradations).
- `GET /health` returns the OpenCV version; `GET /inspect/example/stain.png`
  must return `FAIL` with a `stain` finding; `clean.png` must return `PASS`.
- Failure behaviour is part of the spec: see `evaluation/FAILURE_CASES.md`.

## Layout

- `agent/orchestrator.py` — the agent loop and its tool registry
- `tools_cv/` — OpenCV 5 tools (quality, markers, detection)
- `app/main.py` — FastAPI endpoint + demo page; `app/storage.py` — AWS persistence
- `data/gen_scenes.py` — evaluation scene generator (all imagery is
  generated by this code; no third-party data)
- `infra/` — Dockerfile + SAM template
- `docs/` — diagrams and the technical report

## Responsible use

VigilAgent assists human inspectors; it does not replace them. Critical
or uncertain findings are always escalated (HUMAN_REVIEW), every verdict
carries its evidence and trace, and the system processes workstation
photographs — no people are identified or tracked.
