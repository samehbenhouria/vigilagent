# VigilAgent — Technical Report

**OpenCV AI Competition 2026, powered by AWS**
Team: Sameh Ben Houria (solo) · Category focus: Overall + Agentic Vision Award

## 1. Problem and users

Small food-prep businesses, workshops and labs run visual compliance
checks — is the station complete, clean, correctly labelled? — by memory
and goodwill. Checks get skipped, and when something is wrong there is
no record of what was seen or decided. VigilAgent turns any workstation
photograph into a traceable inspection: a verdict (PASS / FAIL /
HUMAN_REVIEW), the visual evidence behind it, and a complete log of how
the agent reached it. The user is a shift lead or owner who photographs
a station with a phone; the beneficiary is whoever relies on that
station being right.

## 2. System overview

VigilAgent is an autonomous inspection **agent** built on OpenCV 5. It
does not run a fixed pipeline: measurements taken at each step select
the next action.

1. **Plan.** An ArUco marker in the scene identifies the zone. Each zone
   has an enrolled plan: item slots, free areas, label area, the
   expected lot string, and an enrolled reference photograph.
2. **Quality gate.** Blur (Laplacian variance), contrast and exposure
   are measured. If the image is not usable, the agent applies the
   correction that matches the measured issue — CLAHE for low contrast,
   gamma for exposure, sharpening for blur — and re-measures, up to
   three rounds. An image that stays unusable is never judged: the case
   escalates to a human.
3. **Perceive.** The lot label is decoded (QR). The image is aligned to
   the reference with ORB features and a RANSAC homography; a masked
   absolute difference yields candidate defect regions, classified by
   the zone plan (missing item, slot anomaly, stain in a free area,
   foreign object).
4. **Doubt → re-inspect.** Every candidate must be confirmed by an
   independent second look — an enlarged crop re-compared against the
   reference — before it can fail the station. A QR that fails to decode
   is retried on a rectified upscale.
5. **Decide.** Confirmed defects → FAIL. No defects and a verified
   label → PASS. Anything unresolved → HUMAN_REVIEW, with the reason in
   the trace.
6. **Report.** Annotated image, findings with bounding boxes, and the
   full JSON trace. On AWS, the report and evidence persist to S3 with a
   DynamoDB index.

Two safety properties are enforced by design and verified in evaluation:

- **Evidence guard.** Sharpening can make a catastrophically blurred
  image *score* as sharp (ringing raises Laplacian variance). When the
  original blur measurement is catastrophic, defect candidates found on
  that evidence are escalated, never turned into a FAIL.
- **Valid-area masking.** Difference candidates are restricted to the
  area actually warped from the source frame, so rotation/translation
  borders cannot become phantom defects.

## 3. OpenCV 5 implementation

OpenCV 5.0.0 (headless) is the sole vision engine: `cv2.aruco` zone
markers, `cv2.QRCodeDetector`, `cv2.ORB` + `findHomography` alignment,
Laplacian-variance blur measurement, CLAHE (`createCLAHE`), morphology
and contour analysis for regions, perspective warping, and per-region
zoom confirmation. Tools are exposed through a registry with
JSON-described inputs and outputs (MCP-style); the orchestrator is a
deterministic state machine whose every tool call and branch is written
to the trace. No trained model, no external AI API: the system is fully
reproducible from its pinned dependencies.

## 4. AWS deployment

API Gateway (HTTP API) → Lambda on **ARM64/Graviton** running the same
container image as the local demo (FastAPI + OpenCV 5, served through
the AWS Lambda Web Adapter) → S3 evidence store (public access blocked)
and DynamoDB inspection index, with CloudWatch logs and metrics. The
whole stack is declared in `infra/template.yaml` (AWS SAM) and deploys
with `sam build && sam deploy`. Persistence is environment-driven, so
the identical code runs locally with storage off and on AWS with
storage on — verified in both modes.

*Deployment status at submission time is stated in the project README;
the infrastructure is code-complete and the endpoint is demonstrable
from the container in either environment.*

## 5. Evaluation

All imagery is generated by our own code (`data/gen_scenes.py`,
`data/gen_scenes_v2.py`): an enrolled workstation scene with ground
truth by construction, into which defects and degradations are injected.

**Set v1 — 10 cases, 10 handled correctly.** Clean scene PASS; stain,
missing item, foreign object and wrong lot label each FAIL with the
correct finding type; moderate blur recovered to PASS by the quality
gate; perspective absorbed by alignment; low-contrast and underexposed
scenes escalated to HUMAN_REVIEW.

**Set v2 — 8 core cases, 8 handled correctly; 2 challenge cases, 2
handled.** Rotation (8°) and translation PASS after masked alignment;
combined stain + missing item FAIL with both findings; displaced item
FAIL; occluded zone marker, blank frame and catastrophic blur all
escalate; sensor-noise scene PASS; a small stain (30×18 px) and a
rotated stain are both detected, with no phantom findings after masking.

**Latency.** Mean inspection 3.8 s, max 15.9 s on the evaluation host
(multi-retry cases dominate the tail) — comfortably inside the 60 s
Lambda timeout.

**Failure cases (full detail in `evaluation/FAILURE_CASES.md`).**
F1: aggressive multi-issue photometric correction shifted colours and
produced a false FAIL — rejected in favour of one conservative
correction per round. F4: rotation borders produced phantom
foreign-object regions — fixed with valid-area masking. F5: sharpening
ringing on catastrophic blur fooled both the quality metric and the
confirmation detector — fixed with the evidence guard. F3 is a declared
limitation: metrics are measured on generated scenes, which are simpler
than real workstation photographs; thresholds are calibrated on this
set and the calibration data is published in the code.

## 6. Limitations and responsible use

- One enrolled zone, still images, four defect families; video and
  multi-zone operation are future work.
- Reference-based inspection assumes a mostly fixed camera viewpoint;
  alignment tolerates moderate rotation, translation and perspective.
- VigilAgent **assists** inspectors. Critical findings and every
  unresolved case require a human decision; the system never silently
  passes what it could not verify, and every verdict ships with its
  evidence and trace. It processes workstation photographs only — no
  people are identified, tracked or profiled.
